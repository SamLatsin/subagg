# subagg

Агрегатор подписок. Собирает ноды из нескольких внешних подписок и своих
серверов, приводит имена к единому виду, проверяет живость через настоящее
ядро mihomo и отдает результат одной подпиской по токену.

Зачем: на роутерах и телефоне остается один URL вместо трех, фильтры в
профиле mihomo перестают зависеть от того, как провайдер назвал ноду, а
заглушки панелей и протухшие серверы до клиентов не доезжают.

## Запуск

```sh
git clone <репо> subagg && cd subagg
cp .env.example .env
$EDITOR .env          # обязательно поменяй SUBAGG_ADMIN_PASSWORD
docker compose up -d --build
```

Админка на `http://<сервер>:8080/`, логин `admin`, пароль из `.env`.
Язык интерфейса (RU / EN) переключается в правом верхнем углу.

Если при сборке недоступен GitHub, скачай ядро на машине с доступом и
положи рядом с Dockerfile:

```sh
V=v1.19.31
curl -fsSL "https://github.com/MetaCubeX/mihomo/releases/download/$V/mihomo-linux-amd64-$V.gz" | gunzip > mihomo
docker compose build --build-arg MIHOMO_LOCAL=1
```

## Как пользоваться

**1. Добавь подписки.** Имя, URL, User-Agent и заголовки в JSON. Заголовки
нужны панелям, которые проверяют HWID, иначе вместо нод приходят заглушки:

```json
{
  "x-device-os": "OpenWrt",
  "x-ver-os": "24.10.3",
  "x-device-model": "Huasifei WH3000 Pro",
  "x-hwid": "<sha256 от mac-model>"
}
```

Поле «принудительные теги» добавляет тег всем нодам подписки. Удобно, если
у провайдера все серверы whitelist-овые, а в названиях это никак не
отражено: ставь `WL`.

**2. Добавь свои серверы.** Вкладка «Свои ноды» ест три формата:
ссылки `vless://`, кусок clash YAML с `proxies:` и outbound-джейсон xray
(целый конфиг или один outbound). Они получают тег `MY` и в группу TORRENT
по умолчанию не попадают.

**3. Настрой цели проверки.** Нода считается живой, если прошли **все**
обязательные цели и хотя бы одна любая. Мертвой она становится после
`SUBAGG_DEAD_AFTER_FAILS` неудачных прогонов подряд, так что разовый сбой
сети ничего не выбрасывает.

Проверка идет **из того места, где стоит этот сервис**. Если сервис живет
дома на обычном интернете, а роутер выходит через симку с белым списком,
вердикты будут расходиться: мобильные whitelist-ноды отсюда могут
отвечать, а обычные ноды на симке работать не будут. Поэтому фильтрация
по живости убирает только заглушки и реально протухшие серверы, а выбор
рабочей ноды из оставшихся все равно делает `url-test` на роутере.

**4. Создай токены.** По одному на устройство: свой формат и свои
regex-фильтры. Ссылка вида `http://<сервер>:8080/sub/<токен>`. Если сервис
опубликован через reverse proxy, задай `SUBAGG_PUBLIC_URL`, и в админке
ссылки будут сразу с твоим доменом.

У каждого токена есть своя страница («Настроить»). Там видно, какие
серверы он сейчас отдает, а какие нет и почему. Галочками можно выключить
отдельные серверы только для этого токена, поменять фильтры или
приостановить токен. Ссылка при этом не меняется.

Если база потерялась, создай токен заново и в поле «Токен или старая
ссылка» вставь прежнюю ссылку: всё после `/sub/` станет токеном, и
клиенты продолжат работать без перенастройки. Поменять токен у
существующего можно на его странице. Кнопка «Выключить»
в общем списке нод убирает ноду из выдачи всех токенов сразу.

«Обновить подписки» и «Проверить ноды» идут в фоне: страница отвечает
сразу и сама перезагрузится, когда операция закончится.

Порядок нод в выдаче: сначала `WL`, потом свои, дальше по стране и
задержке. Клиенты вроде Happ пингуют список сверху вниз, так на мобильной
сети с белыми списками рабочие ноды находятся первыми.

Формат определяется так: если клиент прислал User-Agent с `clash`,
`mihomo`, `nikki`, `flclash` или `stash`, отдается YAML. Иначе то, что
выбрано у токена. Принудительно: `?format=clash|base64|uri`.

## Схема имен

```
[RU][WL][TOR] 🇷🇺 Россия · s1-4205
```

- `RU` / `XX` / `MY` — регион: Россия, заграница, свой сервер
- `WL` — whitelist, LTE, «обход», то есть ноды под белые списки операторов
- `TOR` — на ноде разрешены торренты
- `GAME` — игровая
- `s1-4205` — подписка и короткий отпечаток, чтобы имена были уникальны

Фильтры в профиле mihomo тогда выглядят так:

```yaml
proxy-providers:
  agg:
    type: http
    url: "http://192.168.30.50:8080/sub/ТОКЕН"
    path: ./providers/agg.yaml
    interval: 1800
    proxy: DIRECT
    health-check:
      enable: true
      url: "https://www.gstatic.com/generate_204"
      interval: 300

proxy-groups:
  - name: RU
    type: url-test
    use: [agg]
    filter: "(?i)^\\[RU\\]"
    url: "https://ya.ru"
    interval: 300
    tolerance: 50
    lazy: false

  - name: FOREIGN
    type: url-test
    use: [agg]
    filter: "(?i)^\\[XX\\]"
    url: "https://www.gstatic.com/generate_204"
    expected-status: 204
    interval: 300
    tolerance: 50
    lazy: false

  - name: TORRENT
    type: url-test
    use: [agg]
    filter: "(?i)\\[TOR\\]"
    url: "https://www.gstatic.com/generate_204"
    interval: 300
    timeout: 6000
    tolerance: 500
    lazy: false

  - name: OWN
    type: url-test
    use: [agg]
    filter: "(?i)^\\[MY\\]"
    url: "https://www.gstatic.com/generate_204"
    expected-status: 204
    interval: 600
```

## Доступ с симки

Если сервис стоит дома, а роутер на симке с белым списком, до дома он не
достучится. Рабочая схема: держать на домашней машине cron, который по
готовности файла кладет его на сервер из белого списка, а роутер тянет
статику оттуда.

```sh
curl -fsS "http://127.0.0.1:8080/sub/ТОКЕН?format=clash" -o /tmp/agg.yaml \
  && grep -q '^proxies:' /tmp/agg.yaml \
  && rsync -e ssh /tmp/agg.yaml wl-srv:/var/www/sub/<длинный-секретный-путь>.yaml
```

Проверка `grep` нужна, чтобы на сервер не уехал пустой или битый файл.

## Про лимит устройств

HWID считается в момент запроса подписки, и тут запрос делает только этот
сервис — значит, слот на панели занимает он один. Но ноды при этом
аутентифицируют по UUID, и панели умеют ограничивать число одновременных
IP на пользователя. То есть раздача конфига на сторону видна и остается
нарушением условий провайдера, даже если технически работает.

Кэш не спасает от истечения подписки: панель синхронизирует пользователей
с нодами, и по окончании срока UUID с серверов снимается. Резерв на этот
случай — только свои серверы.

## Безопасность

В выдаче лежат все UUID и ключи, поэтому:

- закрывай сервис HTTPS-ом через reverse proxy, наружу голым HTTP не свети;
- токен длинный и случайный, но лишний раз его не публикуй;
- смени `SUBAGG_ADMIN_PASSWORD`, дефолтный пароль нерабочий by design;
- том `./data` содержит базу с ключами, в бэкап клади шифрованным.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SUBAGG_ADMIN_PASSWORD` | — | Пароль админки, логин `admin` |
| `SUBAGG_PUBLIC_URL` | — | Внешний адрес для ссылок на подписки, например `https://sub.example.com` |
| `SUBAGG_FETCH_INTERVAL_MIN` | 60 | Как часто обновлять подписки |
| `SUBAGG_CHECK_INTERVAL_MIN` | 30 | Как часто проверять ноды |
| `SUBAGG_CHECK_CONCURRENCY` | 16 | Параллельных проверок |
| `SUBAGG_CHECK_TIMEOUT_MS` | 6000 | Таймаут одной проверки |
| `SUBAGG_DEAD_AFTER_FAILS` | 3 | Провалов подряд до вердикта «мертва» |
| `SUBAGG_CHECKER_DNS` | 1.1.1.1,8.8.8.8,77.88.8.8 | Чем ядро проверки резолвит адреса нод |

## Что внутри

```
app/parsers.py    разбор подписок: base64, ссылки, clash YAML
app/xray.py       outbound xray -> proxy-объект mihomo
app/uri.py        обратная конвертация для выдачи в base64
app/normalize.py  страна по флагу и названию, теги, единое имя
app/fetcher.py    обновление подписок, дедупликация, удаление пропавших
app/checker.py    поднимает mihomo, гоняет delay API, пишет вердикты
app/render.py     сборка итоговой подписки под токен
app/jobs.py       фоновые обновление и проверка, защита от двойного запуска
app/i18n.py       английский перевод админки
app/main.py       FastAPI: выдача, админка, планировщик
```

Ноды дедуплицируются по отпечатку `type|server|port|секрет`, так что один
и тот же сервер из двух подписок попадет в выдачу один раз.

Кривую ноду, из-за которой ядро отказывается стартовать, чекер находит и
выбрасывает сам, остальные при этом проверяются нормально.
